## Overview
`plugin-foreground-service` 是一个 Tauri 移动插件，旨在为 Android 应用提供**前台服务保活**与**开机自启**能力。该插件通过 Kotlin 实现 Android 原生 `Service` 与 `BroadcastReceiver`，并通过 Rust 侧的 `tauri-plugin` 机制暴露命令接口。

核心设计哲学是“**进程壳**”：插件本身不执行复杂的网络监控或自动登录逻辑（这些由 Rust 侧的 `monitor_loop` 处理），而是专注于维持进程存活、管理常驻通知、控制唤醒锁（WakeLock/WifiLock）以及处理厂商特定的电池优化跳转。

## Data Flow

1.  **启动监控**:
    *   Rust 调用 `start_monitor(title)` (`src/lib.rs:33`)。
    *   插件执行 `startMonitor` (`MonitorServicePlugin.kt:50`)。
    *   构造 `Intent` 并调用 `activity.startForegroundService` (`MonitorServicePlugin.kt:64`)。
    *   `ForegroundService.onCreate` (`ForegroundService.kt:159`) 被触发。
    *   服务调用 `startForegroundWithText` (`ForegroundService.kt:317`) 创建通知通道 `campus_monitor_v2` 并显示前台通知。
    *   注册网络监听 `registerNetworkWatcher` (`ForegroundService.kt:226`)。
    *   启动定时刷新任务 `refreshTick` (`ForegroundService.kt:169`)。

2.  **探针巡检 (Probe Window)**:
    *   Rust 侧 `run_check_once` 开始前调用 `begin_probe_window` (`src/lib.rs:47`)。
    *   插件执行 `beginProbeWindow` (`MonitorServicePlugin.kt:142`)。
    *   直接调用 `ForegroundService.beginProbeWindow()` (`ForegroundService.kt:62`)。
    *   服务内部 `acquireProbeLocks` (`ForegroundService.kt:179`) 获取 `WifiLock` (FULL_HIGH_PERF) 和 `PARTIAL_WAKE_LOCK` (带30s超时)。
    *   Rust 执行网络检测。
    *   Rust 侧结束后调用 `end_probe_window` (`src/lib.rs:52`)。
    *   服务内部 `releaseProbeLocks` (`ForegroundService.kt:204`) 释放锁。

3.  **网络变化响应 (Nudge)**:
    *   Android 系统触发 `ConnectivityManager.NetworkCallback.onCapabilitiesChanged` (`ForegroundService.kt:256`)。
    *   计算 `mask` (WiFi/Cellular/Validated 位掩码)。
    *   若 `mask != lastFieldMask` 且超过 `NUDGE_THROTTLE_MS` (5s)，则触发 `nudge()` (`ForegroundService.kt:262`)。
    *   `nudge()` 获取 `PARTIAL_WAKE_LOCK` (`NUDGE_WAKE_MS` = 3s) (`ForegroundService.kt:243`)，确保 Rust 轮询在 CPU 唤醒窗口内执行。

4.  **通知刷新**:
    *   `refreshTick` 每 12 小时 (`REFRESH_INTERVAL_MS`) 执行 (`ForegroundService.kt:152`)。
    *   重置 `startAtMs` 为当前时间，重建通知 (`buildNotification`) 并调用 `manager.notify` (`ForegroundService.kt:155`)。
    *   目的：防止国产 ROM (如澎湃OS) 因通知陈旧度折叠进“更多消息”。

5.  **开机自启**:
    *   系统发出 `BOOT_COMPLETED`。
    *   `BootReceiver.onReceive` (`MonitorServicePlugin.kt:417`) 拦截。
    *   读取 `SharedPreferences` key `boot_autostart` (`MonitorServicePlugin.kt:420`)。
    *   若为 true，尝试启动 `ForegroundService` (`MonitorServicePlugin.kt:427`) 和 `MainActivity` (`MonitorServicePlugin.kt:435`)。
