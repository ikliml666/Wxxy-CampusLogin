## Overview
`rust-plugins-keystore` 是一个 Tauri 移动插件，旨在为 Android 平台提供基于 `AndroidKeyStore` 的安全密钥存储与加解密服务。该模块主要解决移动端敏感数据（如密码）落盘加密的问题，其设计目标与桌面端的 DPAPI 同构：确保密钥不出安全硬件，前端应用无感知地进行明文与密文的转换。

插件采用 Rust 作为核心逻辑层，通过 Tauri 的 Mobile Plugin 机制桥接 Kotlin (Android) 原生实现。它提供了 `encrypt` 和 `decrypt` 两个核心命令，支持 AES-GCM 模式加密，并集成了 Tauri 的标准权限系统以控制前端对加解密能力的访问。

#### Methods

**`private fun getOrCreateKey(): SecretKey`**
*   **定义位置**: `KeystorePlugin.kt` 第 34-48 行
*   **描述**: 从 AndroidKeyStore 获取或生成 AES 密钥。
*   **逻辑**:
    *   尝试加载 `AndroidKeyStore` 并查找 `KEY_ALIAS` 对应的 `SecretKey` (第 35-36 行)。
    *   若不存在，则使用 `KeyGenerator` 生成新的 256 位 AES 密钥 (第 38-47 行)。
    *   配置 `KeyGenParameterSpec`:
        *   Block Mode: `GCM`
        *   Padding: `NONE`
        *   Purpose: `ENCRYPT or DECRYPT`
        *   Key Size: `256`

**`@Command fun encrypt(invoke: Invoke)`**
*   **定义位置**: `KeystorePlugin.kt` 第 50-63 行
*   **描述**: 处理加密命令。
*   **逻辑**:
    *   解析 `EncryptArgs` (第 52 行)。
    *   初始化 `AES/GCM/NoPadding` Cipher (第 54 行)。
    *   执行加密操作 `doFinal` (第 56 行)。
    *   将 IV 和密文拼接后 Base64 编码 (第 57 行)。
    *   返回结果 JSObject `{ "data": ... }` (第 58 行)。
    *   异常处理：捕获异常并记录日志，拒绝调用 (第 60-62 行)。

**`@Command fun decrypt(invoke: Invoke)`**
*   **定义位置**: `KeystorePlugin.kt` 第 65-82 行
*   **描述**: 处理解密命令。
*   **逻辑**:
    *   解析 `DecryptArgs` (第 67 行)。
    *   Base64 解码原始数据 (第 68 行)。
    *   校验长度必须大于 `IV_LEN` (12)，否则抛出异常 (第 69 行)。
    *   提取前 12 字节作为 IV，剩余部分作为密文 (第 70-71 行)。
    *   初始化 Cipher 为 DECRYPT_MODE，使用 `GCMParameterSpec` (第 71 行)。
    *   执行解密 `doFinal` (第 72 行)。
    *   返回结果 JSObject `{ "text": ... }` (第 74 行)。
    *   异常处理：捕获异常并记录日志，拒绝调用 (第 76-78 行)。

## Data Flow

1.  **Initialization**:
    *   Tauri 应用启动时，调用 `android/plugins/keystore/src/lib.rs` 中的 `init()` 函数。
    *   在 Android 平台上，注册 Kotlin 类 `com.campuslogin.plugin.keystore.KeystorePlugin`。
    *   创建 `CampusKeystore` 实例并存入 Tauri 状态管理器。

2.  **Encryption Request**:
    *   前端 JavaScript 调用 `tauri.invoke('encrypt', { text: 'plaintext' })`。
    *   Rust 侧 `CampusKeystore.encrypt()` 被触发，序列化参数为 JSON `{ "text": "..." }`。
    *   通过 `run_mobile_plugin` 将调用转发至 Android 原生侧。
    *   Kotlin `KeystorePlugin.encrypt()` 接收调用：
        *   检查 `AndroidKeyStore` 是否存在 `campus_login_master` 密钥。
        *   若不存在，使用 `KeyGenerator` 生成新的 256-bit AES 密钥并存储于 Keystore。
        *   使用 `Cipher.getInstance("AES/GCM/NoPadding")` 进行加密。
        *   获取生成的 IV (12 bytes)。
        *   将 `IV || Ciphertext` 拼接，并进行 Base64 编码。
        *   返回 JSObject `{ "data": "<base64_string>" }`。
    *   Rust 侧解析返回的 `EncryptResult`，提取 `data` 字符串返回给前端。

3.  **Decryption Request**:
    *   前端 JavaScript 调用 `tauri.invoke('decrypt', { data: '<base64_string>' })`。
    *   Rust 侧 `CampusKeystore.decrypt()` 被触发，序列化参数为 JSON `{ "data": "..." }`。
    *   通过 `run_mobile_plugin` 转发至 Android 原生侧。
    *   Kotlin `KeystorePlugin.decrypt()` 接收调用：
        *   Base64 解码输入字符串。
        *   验证长度 > 12 字节。
        *   分离前 12 字节为 IV，剩余为密文。
        *   使用相同的密钥别名从 Keystore 获取密钥。
        *   初始化 `Cipher` 为 DECRYPT_MODE，传入 `GCMParameterSpec(128, iv)`。
        *   执行解密。若密文篡改或 IV 不匹配，GCM 认证失败抛出异常。
        *   返回 JSObject `{ "text": "<plaintext>" }`。
    *   Rust 侧解析返回的 `DecryptResult`，提取 `text` 字符串返回给前端。

## Known Issues

1.  **Key Rotation**: 当前实现中，密钥别名 `campus_login_master` 是硬编码的 (KeystorePlugin.kt:30)。如果未来需要轮换密钥，可能需要修改代码或引入更复杂的密钥版本管理逻辑。目前密钥一旦生成即永久使用。
2.  **IV Length Assumption**: 代码假设 IV 长度固定为 12 字节 (KeystorePlugin.kt:31, 71)。虽然 GCM 标准允许不同长度的 IV，但此处硬编码可能导致与其他系统交互时的兼容性问题，如果其他系统使用标准 12 字节 (96-bit) IV 则正常，否则需调整。
3.  **Error Handling Granularity**: Kotlin 端的异常处理较为笼统，所有加密/解密失败都返回通用的 "Keystore 加密失败" 或 "Keystore 解密失败" 消息 (KeystorePlugin.kt:62, 78)。对于调试而言，缺乏具体的错误码区分（如密钥不存在、密文损坏、硬件故障等）。
