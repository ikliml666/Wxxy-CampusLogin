## Overview
`rust-plugins-network-bind` (包名 `tauri-plugin-campus-network-bind`) 是 Tauri 移动端插件，专为 Android 平台设计。其核心功能是将应用进程的网络流量强制绑定到 WLAN（Wi-Fi）接口，确保校园网登录等特定场景下的流量不走移动数据。

该模块通过 JNI 桥接 Kotlin 原生 Android API (`ConnectivityManager`, `WifiManager`) 与 Rust 侧。它处理了复杂的网络状态管理，包括 captive portal（认证门户）处理、VPN 冲突检测、WiFi 变化监听以及系统级设置（`Settings.Global`）的读写与还原。

主要特性：
1. **进程级网络绑定**：使用 `bindProcessToNetwork` 将新创建的 socket 绑定到指定 WiFi 网络。
2. **Captive Portal 处理**：自动尝试接受无互联网连接的校园网，避免用户手动点击“仍然连接”。
3. **系统设置管理**：程序化控制 `network_avoid_bad_wifi` 和 `captive_portal_mode`，支持快照与还原机制。
4. **WiFi 监控**：监听 WiFi 连接、断开及验证状态变化。
5. **权限与安全**：精细化的权限请求（如 `NEARBY_WIFI_DEVICES`）和隐藏 API 探测。

## Data Flow

1. **Binding Process (`bindToWifi`)**:
   - Rust calls `bind_to_wifi`.
   - Kotlin iterates `allNetworks`, filters for WiFi transport.
   - Prioritizes networks with `NET_CAPABILITY_INTERNET`.
   - Attempts `bindProcessToNetwork`.
   - If failed, checks for VPN.
   - Falls back to `requestNetwork` with a custom `NetworkRequest` (explicitly removing `INTERNET` capability to avoid AOSP rejection for captive portals).
   - Returns result `{bound, path, reason}`.

2. **Captive Portal Acceptance (`acceptWifiNetwork`)**:
   - Rust calls `accept_wifi_network`.
   - Kotlin detects if network is already validated.
   - Tries Hidden API `setAcceptUnvalidated` via reflection.
   - If Hidden API fails (SecurityException/NoSuchMethod), falls back to writing `Settings.Global.captive_portal_mode=0` and `network_avoid_bad_wifi=0`.
   - Snapshots original values before writing for later restoration.

3. **System Settings Management (`ensureAvoidBadWifi` / `restore...`)**:
   - Requires `WRITE_SECURE_SETTINGS` permission (via adb pm grant).
   - `ensure`: Reads current value, snapshots it, writes `1`.
   - `restore`: Reads snapshot from `SharedPreferences`, writes back, removes snapshot.

4. **WiFi Monitoring (`startWifiWatcher`)**:
   - Rust creates a `Channel`.
   - Kotlin registers `NetworkCallback`.
   - Events (`available`, `lost`, `validated`, `unvalidated`) are emitted via `trigger("wifiChanged", payload)` to the Rust channel.

## Known Issues

1. **VPN Conflict**: `bindProcessToNetwork` returns `false` if any VPN is active. The plugin detects this and returns `reason="bind_false_vpn_active"`. User must disable VPN. (Source: `NetworkBindPlugin.kt` Line 105-107, Class Comment).
2. **Captive Portal Rejection**: Using `NET_CAPABILITY_INTERNET` in `NetworkRequest` causes AOSP to reject the request for captive portal networks. The plugin explicitly removes this capability. (Source: `NetworkBindPlugin.kt` Line 110, Class Comment).
3. **Hidden API Access**: `setAcceptUnvalidated` is hidden. It may fail on some ROMs or Android versions due to hidden API restrictions. The plugin gracefully falls back to `Settings.Global` write. (Source: `NetworkBindPlugin.kt` Line 182-188).
4. **SSID Permissions**: On Android < 33, getting SSID requires `ACCESS_FINE_LOCATION` and GPS enabled. The plugin does not request location permissions, so SSID is empty on older devices. (Source: `NetworkBindPlugin.kt` Line 307-320).
