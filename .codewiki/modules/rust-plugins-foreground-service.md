## Overview

`rust-plugins-foreground-service` (内部标识 `tauri-plugin-campus-monitor-service`) 是 Tauri Android 插件，负责为校园网监控应用提供**前台服务保活**与**系统级权限引导**。

核心职责：
1. **进程存活**：通过 Android Foreground Service (FGS) 维持常驻通知，防止被系统回收。
2. **网络探针保活**：在 Rust 侧执行网络检测时，按需持有 `WifiLock` 和 `WakeLock`，确保探测期间 WiFi 不断流、CPU 不被休眠。
3. **省电策略优化**：避免常驻持有高功耗锁，仅在必要窗口期（探针或网络状态翻转）短持唤醒锁。
4. **自启与白名单**：提供开机自启开关、电池优化白名单申请及厂商特定设置页跳转逻辑。

业务逻辑（如心跳检测、自动重登）完全由 Rust 侧驱动，本插件仅作为底层基础设施。

#### `ForegroundService` (类)
*文件*: `android/plugins/foreground-service/android/src/main/java/com/campuslogin/plugin/monitorservice/ForegroundService.kt`

前台服务实现，负责通知展示、锁管理和网络监听。

**常量**:
- `CHANNEL_ID = "campus_monitor_v2"` (行 24): 通知通道 ID。
- `NOTIFICATION_ID = 0xCAFE` (行 25): 通知 ID。
- `EXTRA_TEXT = "text"` (行 26): Intent 额外数据 Key。
- `ACTION_UPDATE` / `ACTION_STOP` (行 27-28): 广播 Action。
- `NUDGE_THROTTLE_MS = 5000L` (行 37): 网络变化唤醒锁节流间隔。
- `NUDGE_WAKE_MS = 3000L` (行 41): Nudge 唤醒锁持有时长。
- `PROBE_WINDOW_TIMEOUT_MS = 30_000L` (行 45): 探针窗口唤醒锁超时时间。
- `REFRESH_INTERVAL_MS = 12 * 60 * 60 * 1000L` (行 61): 通知定时刷新间隔 (12小时)。

**静态字段**:
- `instance: ForegroundService?` (行 51): 当前服务实例引用。
- `isRunning: Boolean` (行 56): 运行状态标志。
- `startAtMs: Long` (行 65): 通知计时器起点。
- `lastText: String` (行 71): 最后构建的通知文案。

**静态方法**:
- `beginProbeWindow()` (行 58): 调用实例的 `acquireProbeLocks()`。
- `endProbeWindow()` (行 61): 调用实例的 `releaseProbeLocks()`。
- `buildNotification(context: Context, text: String)` (行 80-98): 构建标准 Android 通知。
    - 特性: `ongoing=true`, `usesChronometer=true`, `CATEGORY_SERVICE`。
    - 兼容: Android O+ 使用 NotificationChannel。
- `mainActivityIntent(context: Context)` (行 100-110): 生成点击通知跳转 MainActivity 的 PendingIntent。

**实例字段**:
- `wifiLock: WifiManager.WifiLock?` (行 117): 抑制 WiFi 省电的锁。
- `nudgeWakeLock: PowerManager.WakeLock?` (行 118): 网络状态变更时的短持唤醒锁。
- `probeWakeLock: PowerManager.WakeLock?` (行 119): 探针窗口期间的长持唤醒锁。
- `networkCallback: ConnectivityManager.NetworkCallback?` (行 120): 网络回调注册对象。
- `refreshHandler` / `refreshTick` (行 124-131): Handler 用于每 12 小时重建通知以防折叠。

**实例方法**:
- `onCreate()` (行 133-144): 初始化通知、注册网络监听、设置实例引用。
- `acquireProbeLocks()` (行 146-167): 获取探针锁。
    - 创建 `WifiLock` (若为空)，模式 `WIFI_MODE_FULL_HIGH_PERF`。
    - 获取 `PARTIAL_WAKE_LOCK`，带 30s 超时。
- `releaseProbeLocks()` (行 169-179): 释放探针锁 (幂等)。
- `registerNetworkWatcher()` (行 181-222): 注册网络能力变更回调。
    - 去重逻辑: 基于 `TRANSPORT_WIFI`/`CELLULAR` 和 `VALIDATED` 位掩码比对，避免高频连发。
    - 节流: 两次 nudge 间隔至少 5s。
- `releaseLocks()` (行 224-237): 清理所有锁和网络回调。
- `onStartCommand()` (行 239-249): 处理 ACTION_STOP 或更新通知文本。
- `onDestroy()` (行 251-258): 移除刷新任务，释放锁，重置状态。
- `startForegroundWithText(text: String)` (行 260-281): 启动前台服务。
    - 创建 IMPORTANCE_DEFAULT 通道，静音无角标。
    - 删除旧版 `IMPORTANCE_LOW` 通道。
    - Android U+ 使用 `FOREGROUND_SERVICE_TYPE_SPECIAL_USE`。

## Data Flow

### 1. 监控循环与探针保活 (Monitor Loop & Probe Window)
这是最核心的性能与稳定性流程。

1. **Rust 发起**: `monitor_loop` 准备执行一次网络检测。
2. **获取锁**: 调用 `rust-plugins-foreground-service` 的 `begin_probe_window()`。
   - 对应 Kotlin: `MonitorServicePlugin.beginProbeWindow` -> `ForegroundService.beginProbeWindow` -> `ForegroundService.acquireProbeLocks`。
   - **动作**: 获取 `WifiLock` (防止 WiFi 省电断流) 和 `PARTIAL_WAKE_LOCK` (防止 CPU 休眠)。
3. **执行检测**: Rust 侧进行 HTTP/DNS 探测。
4. **释放锁**: 检测完成（无论成功失败），调用 `end_probe_window()`。
   - 对应 Kotlin: `MonitorServicePlugin.endProbeWindow` -> `ForegroundService.endProbeWindow` -> `ForegroundService.releaseProbeLocks`。
   - **注意**: `acquireProbeLocks` 中的 WakeLock 设置了 `PROBE_WINDOW_TIMEOUT_MS` (30s) 超时，即使 Rust 侧异常未调用 release，系统也会在 30s 后强制释放，防止死锁。

### 2. 网络状态变更 (Network Capability Change)
1. **系统事件**: Android 网络栈检测到 WiFi/蜂窝切换或连接质量变化。
2. **回调触发**: `ForegroundService.registerNetworkWatcher` 中的 `onCapabilitiesChanged`。
3. **过滤**: 计算 `mask` (WiFi bit0, Cellular bit1, Validated bit2)。若 `mask != lastFieldMask` 则继续。
4. **节流**: 检查 `System.currentTimeMillis() - lastNudgeMs < NUDGE_THROTTLE_MS` (5s)。若满足则丢弃。
5. **Nudge**: 若通过过滤，获取 `nudgeWakeLock` (3s 超时)。
6. **Rust 响应**: 唤醒后的下一个 Rust 巡检 tick 会检测到网络变化并执行相应逻辑。

### 3. 通知防折叠 (Notification Anti-Fold)
1. **问题**: 长期不更新的通知会被国产 ROM (如澎湃 OS) 折叠进“更多消息”。
2. **机制**: `ForegroundService.refreshTick` Runnable。
3. **周期**: 每 `REFRESH_INTERVAL_MS` (12小时) 触发一次。
4. **动作**: 更新 `startAtMs` 为当前时间，重新构建并发送通知。
   - 这重置了 Chronometer 计时，并使通知被视为“活跃”，避免被降权。

### 4. 开机自启 (Boot Autostart)
1. **触发**: `BootReceiver.onReceive` 接收到 `ACTION_BOOT_COMPLETED`。
2. **检查**: 读取 `SharedPreferences` (`campus_settings`) 中的 `boot_autostart` boolean。
3. **执行**:
   - 若为 true，尝试 `startForegroundService` 和 `startActivity(MainActivity)`。
   - 启动失败仅记录日志，不阻塞其他应用组件。

## Known Issues

1. **Android 13+ 通知权限**:
   - 本插件生成的常驻通知属于 `CATEGORY_SERVICE`，通常不受 `POST_NOTIFICATIONS` 运行时权限限制（因为它是前台服务的一部分）。但如果用户在全局设置中关闭了该应用的所有通知，前台服务仍会运行，但通知可能不可见。
   - 提供了 `openNotificationSettings` 供用户手动开启。

2. **厂商 ROM 兼容性**:
   - `openVendorBatterySettings` 使用了大量的 `ComponentName` 硬编码。随着 ROM 版本迭代，类名可能漂移。代码实现了逐级 `try-catch` 降级到应用详情页，但无法保证 100% 直达目标页面。
   - 小米/红米等厂商对后台启动 Activity 有严格限制，`BootReceiver` 中启动 `MainActivity` 可能会被静默拦截，此时仅保留前台服务通知。

3. **WifiLock 耗电**:
   - `WIFI_MODE_FULL_HIGH_PERF` 会禁止 WiFi 进入省电模式。因此必须严格控制在 `Probe Window` 内使用。代码中 `acquireProbeLocks` 和 `releaseProbeLocks` 成对出现，且 WakeLock 带有超时保护，以降低风险。

4. **Notification Channel 升级**:
   - 代码中显式删除了旧的 `campus_monitor` (IMPORTANCE_LOW) 通道，新建 `campus_monitor_v2` (IMPORTANCE_DEFAULT)。如果用户从极老版本升级，旧通道可能已被系统清理或不再存在，此操作应安全；若存在冲突，可能导致短暂的通知显示异常。
