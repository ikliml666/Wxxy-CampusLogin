## Overview

`android/plugins/` 下三个**手写 Tauri 移动插件**（Rust 壳 + Kotlin 实现），承接安卓平台专属能力：`keystore` 提供 AndroidKeyStore AES-GCM 加解密原语（替代桌面 DPAPI），`network-bind` 把进程网络绑定到 WLAN（`bindProcessToNetwork`）并上报 WiFi 变化事件，`foreground-service` 负责前台服务保活（常驻通知 + 探针窗口内按需持有的 WifiLock/WakeLock，见 `beginProbeWindow`/`endProbeWindow`）、开机自启与 APK 安装。

三者都是"薄壳"结构：Rust 侧只有一个 `PluginHandle` 包装 + `Ext` trait（供 `app.campus_xxx()` 取用），业务逻辑全在 Kotlin；Rust 壳与 Kotlin 通过 `run_mobile_plugin(命令名, 参数)` / `trigger(事件名, payload)` 通信。业务逻辑（登录协议、监控循环、自动重登）**不在插件里**，全在 Rust 侧 [[android-backend]] 的 `monitor_loop.rs`，插件只保证进程活着、走对网络、能加解密。

三个插件的 crate 名与调用方（`android/src-tauri/Cargo.toml:37/40/43`）：

| 目录 | crate 名 | 注册名 | Android plugin 类 | 主要调用方 |
|------|----------|--------|-------------------|-----------|
| `android/plugins/keystore` | `tauri-plugin-campus-keystore` | `campus-keystore` | `com.campuslogin.plugin.keystore.KeystorePlugin` | `config_state.rs:133-162`（`CryptoBridge::from_app`） |
| `android/plugins/network-bind` | `tauri-plugin-campus-network-bind` | `campus-network-bind` | `com.campuslogin.plugin.networkbind.NetworkBindPlugin` | `protocol_cmds.rs:175-206`、`monitor_loop.rs:218-252` |
| `android/plugins/foreground-service` | `tauri-plugin-campus-monitor-service` | `campus-monitor-service` | `com.campuslogin.plugin.monitorservice.MonitorServicePlugin` | `monitor_loop.rs:160-207`、`battery_cmds.rs`、`update_cmds.rs:405` |

三者的 `src/lib.rs` 首行均为 `#![cfg(mobile)]`（`keystore/src/lib.rs:1`、`network-bind/src/lib.rs:1`、`foreground-service/src/lib.rs:1`），host（Windows）编译时整个 crate 为空。

## Data Flow

### 编译期：权限与 schema 生成

```text
插件 build.rs:  tauri_plugin::Builder::new(COMMANDS).android_path("android").try_build()
   ├─ 读取 android/ 下的 Kotlin 工程（android_path）
   ├─ 为 COMMANDS 中每个命令生成 permissions/autogenerated/commands/<命令>.toml（allow-<cmd> / deny-<cmd>）
   ├─ 生成 permissions/autogenerated/reference.md 与 permissions/schemas/schema.json
   └─ docsrs 特例：仅在非 docsrs 或非 android target 时 unwrap（如 keystore/build.rs:7-9）
Cargo.toml 的 links = "tauri-plugin-campus-<x>" 保证每个插件只允许一个 build script
```

因此 **`permissions/autogenerated/` 与 `reference.md`、`schemas/schema.json` 是构建产物**，改权限必须改 `build.rs` 的 `COMMANDS` + `permissions/default.toml` 后重跑构建，不能手改生成文件。

### 运行期：Rust → Kotlin（命令调用）

```text
调用方（如 config_state.rs:143 的 handle.campus_keystore().encrypt(text)，闭包定义于 `config_state.rs:140-145`）
  → CampusKeystore::encrypt（keystore/src/lib.rs:30）
  → PluginHandle::run_mobile_plugin("encrypt", {"text": ...})
  → JNI → Kotlin PluginManager 按 @Command 方法名路由 → KeystorePlugin.encrypt（KeystorePlugin.kt:57）
  → AndroidKeyStore / Android API
  → JSObject 返回 → Rust 反序列化为 EncryptResult / serde_json::Value
```

`campus_keystore()` 等扩展方法通过 `state::<T>()`（如 `keystore/src/lib.rs:48`）取插件在 `setup` 阶段 `manage` 的句柄（`keystore/src/lib.rs:57`）。

### 运行期：Kotlin → Rust（事件回传）

```text
NetworkBindPlugin.emitWifiEvent（NetworkBindPlugin.kt:296-300）
  → trigger("wifiChanged", {"event": "available|lost|validated|unvalidated"})
  → 基类 registerListener 建立的 channel（Plugin.kt:201；Rust 侧经 CampusNetworkBind::start_wifi_watcher 注册，network-bind/src/lib.rs:32-43）

```

## Connections

- [[android-backend]]：三个插件的唯一调用方（`config_state.rs`、`protocol_cmds.rs`、`monitor_loop.rs`、`battery_cmds.rs`、`update_cmds.rs`）。
- [[desktop-platform]]：Keystore 对应桌面 DPAPI；`platform/identity.rs` 是同构验证门而非本插件能力。
- [[desktop-monitor]]：监控循环语义（检测/自动重登/注销保护）在 Rust 侧，插件只提供保活与电源状态。
- [[desktop-network-core]]：`clear_client_pool` 是网络绑定生效的关键配套。
- [[desktop-helper-update]]：桌面更新安装（exe/msi）对应本插件的 `installApk`（APK）。
- [[android-frontend]]：前端不直接 invoke 插件命令（capabilities 未授予），一律经后端命令间接使用。

## Known Issues

1. **network-bind 的 `default.toml` 权限名悬空**：`network-bind/permissions/default.toml:7` 写的是 `allow-bind-to-wifi` 与 `allow-accept-wifi-network`（kebab-case），但生成器按命令名产出的是 `allow-bindToWifi` / `allow-acceptWifiNetwork`（`permissions/autogenerated/commands/bindToWifi.toml:6`、`acceptWifiNetwork.toml:6`）。前者在权限表中不存在；只有 `allow-unbind` 恰好对上。
2. **network-bind 的命令集与权限集不一致**：`build.rs:1` 只声明 `bindToWifi`/`unbind`/`acceptWifiNetwork` 三个命令，而 Kotlin 侧还有 `startWifiWatcher`（`NetworkBindPlugin.kt:307`）与 `stopWifiWatcher`（`:345`）两个 `@Command`，`permissions/autogenerated/commands/` 下也没有它们的 toml。Rust 经 `run_mobile_plugin` 调用（`network-bind/src/lib.rs:42`、`:53`）不受 ACL 影响故能工作，但若将来前端直接 `invoke` 这两个命令会被权限层拒绝。
3. **foreground-service 的 `default.toml` 有 6 个悬空权限**：`default.toml:7-20` 列 12 项，而 `build.rs:1` 只注册 6 个命令 → `allow-beginProbeWindow`、`allow-endProbeWindow`、`allow-getPowerState`、`allow-getBatteryOptimizationInfo`、`allow-requestIgnoreBatteryOptimizations`、`allow-openVendorBatterySettings` 无对应定义文件；生成文档 `permissions/autogenerated/reference.md` 的 Default Permission 段列 12 项、Permission Table 只有 6 组，自相印证。
4. **悬空引用不会在构建期暴露**：`android/src-tauri/capabilities/default.json` 只引用 `core:default`、`biometric:default`、`opener:default`、`notification:default`，未引用三个插件的 default 权限集，因此上面两类不一致不会触发 ACL 校验报错；代价是前端无法直接 invoke 任何插件命令（当前设计如此，属预期）。
5. **`acceptWifiNetwork` 两条底层路径对普通签名应用实际不可用**：反射 `setAcceptUnvalidated` 需 `CONNECTIVITY_INTERNAL` 且受 hidden API 名单限制（`NetworkBindPlugin.kt:161-164`），`Settings.Global` 写入受 `WRITE_SECURE_SETTINGS`（signature|privileged）保护（`NetworkBindPlugin.kt:251-255`）→ 返回多为 `accepted=false`、`path="none"`。Rust 侧只记日志不阻断（`protocol_cmds.rs:296-330`），不影响主链路。
6. **`bindProcessToNetwork` 只影响此后新建的 socket**（`NetworkBindPlugin.kt:38-39` 类注释）：绑定生效依赖 Rust 侧清空连接池（`protocol_cmds.rs:232-236`），且 `already_bound` 分支刻意不清池；任何绕过 `ensure_wifi_bound` 的新建连接都可能落回默认路由。
7. **`unbind` 无 Rust 调用方**：`NetworkBindPlugin.kt:145` 的 `unbind` 命令在 `android/src-tauri/src/` 中无任何调用点（grep 未命中），`default.toml:7` 却授予其权限——属预留能力（`unbind` 也是唯一清空 `lastBoundNetwork` 记忆的入口，见 `NetworkBindPlugin.kt:151`）。
8. **探针窗口在服务未启动时静默失效**：`ForegroundService.kt:52/55` 用 `instance?.` 安全调用，`instance` 仅在 `onCreate`（`:109`）到 `onDestroy`（`:250`）之间非空。若 `beginProbeWindow` 早于服务创建（或服务被杀），Rust 侧拿不到锁也不报错，探针窗口退化为无锁运行（功能不受影响，省电优化失效）。
9. **`updateNotification` 依赖服务已建通道**：`MonitorServicePlugin.kt:71-75` 直接 `notify(NOTIFICATION_ID, ...)`，通道由服务侧 `startForegroundWithText` 创建（`ForegroundService.kt:261-263`）；服务未启动时在 Android 8+ 上通知会被丢弃（无报错）。Rust 侧调用点 `monitor_loop.rs:771` 亦忽略返回值。
10. **`TextArgs` 被两个语义不同的命令共用**：`installApk`（`MonitorServicePlugin.kt:84`）与 `updateNotification`（`:69`）都解析 `TextArgs{text}`，Rust 壳也统一传 `{"text": ...}`（`foreground-service/src/lib.rs:43`、`:76`）——参数键名错用不会被类型系统拦住。
11. **`installApk` 的双重路径约束**：Rust 侧先 `canonicalize` 限定 `app_data_dir/update/`（`update_cmds.rs:412-417`），Kotlin 侧再用 `File(args.text).name` 重拼 `filesDir/update/`（`MonitorServicePlugin.kt:86-87`）。两端假设同一目录（`app_data_dir` == `filesDir`）；`install_update` 在 `update` 目录 canonicalize 失败时回退未规范化路径（`update_cmds.rs:414`），此时 Rust 侧校验基于非规范化路径。
12. **FileProvider authority 硬编码 `${applicationId}.fileprovider`**（`android/src-tauri/gen/android/app/src/main/AndroidManifest.xml:62`）与 Kotlin 的 `${activity.packageName}.fileprovider`（`MonitorServicePlugin.kt:93`）必须一致；更改 applicationId 后需同时确认两处与 `file_paths.xml`（`android/src-tauri/gen/android/app/src/main/res/xml/file_paths.xml`，含 `<files-path name="update" path="update/"/>`）仍成立。注意这三处都在 `android/src-tauri/gen/` 生成目录内或依赖其配置。
13. **Keystore 密钥与包名/签名绑定**：密钥 alias `campus_login_master`（`KeystorePlugin.kt:34`）由 AndroidKeyStore 按应用签名隔离；换签名或清除应用数据会导致旧密文无法解密，此时 `config_state::load_file` 把密码置空继续加载（`config_state.rs:183-188`），用户需重新输入密码。
14. **`decrypt` 的入参校验很弱**：只 `require(raw.size > IV_LEN)`（`KeystorePlugin.kt:78`），长度合法但内容被篡改时靠 GCM 认证失败拒绝（`:87`）；Rust 侧把任何 decrypt 错误都当"置空"（`config_state.rs:184`），不会向用户报错。
15. **三份 vendored `android/.tauri/tauri-api/` 需人工跟进上游**：每个插件目录下各有一份 `tauri-api` 源码副本（由 `build.rs` 的 `android_path("android")` 引入，`android/build.gradle.kts` 用 `implementation(project(":tauri-android"))`），三份内容独立、共约 28 个 Kotlin 文件，插件基类命令（`registerListener`/`removeListener`，`Plugin.kt:201`/`:215`）也来自这里——升级 tauri-api 时要同步三份。
16. **`build.rs` 的 docsrs 特例掩盖了 android 目标构建失败**：三个插件的 `build.rs:7-9` 在 `docsrs && TARGET contains android` 时跳过 `unwrap()`，本地开发若不满足该条件仍会 panic——属上游模板惯例，但排障时容易误读为"构建通过"。
17. **三个插件均为 mobile-only**：`keystore/src/lib.rs:1`、`network-bind/src/lib.rs:1`、`foreground-service/src/lib.rs:1` 都是 `#![cfg(mobile)]`，host 测试环境拿不到实现；`PLUGIN_IDENTIFIER` 又限定 `#[cfg(target_os = "android")]`（`keystore/src/lib.rs:12` 等），`init` 的 `setup` 里 `handle` 变量在非 android 的 mobile target（iOS）会缺失——本项目仅安卓，不构成实际缺陷，但移植时需补。
