## Overview
本模块涵盖 Android 端 Tauri 应用的完整外壳构建、原生插件实现及操作系统级配置。核心目标是为跨平台应用提供 Android 特有的保活能力、安全存储及网络路由控制。架构由 Rust 侧驱动业务逻辑，Kotlin 层封装底层系统 API 并通过 JNI/IPC 桥接。主要组件包括前台服务插件（保活/通知）、密钥存储插件（AES-GCM）及网络绑定插件（强制 WiFi 路由）。

## Key Components

### 1. 构建与发布脚本
#### `android/build-apk.ps1`
*   **职责**：Windows PowerShell 一键打包脚本，独立于桌面发布流程。
*   **关键实现**：
    *   **环境校验**：强制设置 `[Console]::OutputEncoding = UTF8` 防止 GBK 终端乱码 (`build-apk.ps1:11-12`)。优先使用环境变量 `JAVA_HOME`，若缺失则硬编码回退至 `C:\Users\ik\AppData\Local\Android\jdk\jdk-17.0.20.1+1` (`build-apk.ps1:19-21`)。
    *   **前端构建**：仅在 `node_modules` 不存在时执行 `npm install`，随后执行 `npx vite build` (`build-apk.ps1:27-41`)。
    *   **APK 构建**：调用 Tauri CLI `tauri android build --target aarch64 --apk` (`build-apk.ps1:50`)。
    *   **签名校验与补签**：查找 `apksigner.bat` 验证签名；若未签名，使用 `.android\debug.keystore` 执行 `zipalign` + `apksigner sign` (`build-apk.ps1:65-89`)。默认密码为 `android` (`build-apk.ps1:84`)。

    *   **执行命令**：硬编码 Node.js 路径 (`C:\Program Files\nodejs\node.exe`) 和 Tauri CLI 路径 (`E:\ik\...node_modules\@tauri-apps\cli\tauri.js`) (`BuildTask.kt:19, 52`)。执行 `tauri android android-studio-script` 命令，根据 `release` 和 `target` 添加参数 (`BuildTask.kt:47-69`)。

### 2. 前台服务插件 (Foreground Service)
#### `android/plugins/foreground-service/android/src/main/java/com/campuslogin/plugin/monitorservice/ForegroundService.kt`
*   **职责**：前台服务核心，负责保活、常驻通知展示、探针窗口锁管理。
*   **关键常量**：
    *   `CHANNEL_ID = "campus_monitor_v2"`：版本化通道 ID，避免旧低重要性通道被折叠 (`ForegroundService.kt:34`)。
    *   `NOTIFICATION_ID = 0xCAFE` (`ForegroundService.kt:35`)。
    *   `NUDGE_THROTTLE_MS = 5000L`：网络事件节流间隔 (`ForegroundService.kt:46`)。
    *   `REFRESH_INTERVAL_MS = 12h`：定时刷新通知以防 ROM 折叠 (`ForegroundService.kt:93`)。
*   **关键方法**：
    *   `buildNotification`：构建标准通知，含 Chronometer 计时器，点击跳转 MainActivity (`ForegroundService.kt:103-121`)。
    *   `acquireProbeLocks` / `releaseProbeWindow`：同步方法，管理 `WifiLock` (全性能模式) 和 `PARTIAL_WAKE_LOCK` (带超时 30s)，供 Rust 侧巡检调用 (`ForegroundService.kt:178-214`)。
    *   `registerNetworkWatcher`：监听网络变化，按字段掩码去重后触发 `nudge()` 唤醒 CPU，避免弱信号高频回调 (`ForegroundService.kt:226-273`)。
    *   `startForegroundWithText`：创建 IMPORTANCE_DEFAULT 通道，删除旧 `campus_monitor` 通道，适配 Android 14+ `FOREGROUND_SERVICE_TYPE_SPECIAL_USE` (`ForegroundService.kt:317-338`)。

#### `android/plugins/foreground-service/android/src/main/java/com/campuslogin/plugin/monitorservice/MonitorServicePlugin.kt`
*   **职责**：Tauri 插件入口，暴露 Kotlin 方法给 Rust/JS。
*   **关键命令**：
    *   `startMonitor(title)`：启动 FGS，处理 `IllegalStateException` 防止后台启动失败 (`MonitorServicePlugin.kt:49-76`)。
    *   `stopMonitor`：发送 `ACTION_STOP` 意图让服务自杀 (`MonitorServicePlugin.kt:79-87`)。
    *   `updateNotification(text)`：直接调用 `ForegroundService.buildNotification` 更新通知 (`MonitorServicePlugin.kt:101-117`)。
    *   `installApk(text)`：从 `filesDir/update/` 获取 APK，通过 `FileProvider` 生成 URI 启动安装器，防路径逃逸 (`MonitorServicePlugin.kt:109-137`)。
    *   `beginProbeWindow` / `endProbeWindow`：静态调用 Service 方法，无 IPC 开销 (`MonitorServicePlugin.kt:142-152`)。
    *   `getPowerState`：返回 `{screenOn, wifiConnected}`，供 Rust 决定巡检间隔 (`MonitorServicePlugin.kt:161-179`)。
    *   `openVendorBatterySettings`：复杂的降级链，尝试小米/华为/OPPO/vivo 等厂商特定组件，失败则跳应用详情页或通用设置，返回 `tried` 列表供前端调试 (`MonitorServicePlugin.kt:284-338`)。
    *   `setBootAutostart` / `isBootAutostartEnabled`：操作 `BootReceiver` 组件状态及 SharedPreferences (`MonitorServicePlugin.kt:401-428`)。
    *   `BootReceiver`：接收 `BOOT_COMPLETED`，检查 SharedPreferences 决定是否拉起 FGS 和 MainActivity，捕获异常防止广播崩溃 (`MonitorServicePlugin.kt:416-441`)。

### 4. 网络绑定插件 (Network Bind)
#### `android/plugins/network-bind/android/src/main/java/com/campuslogin/plugin/networkbind/NetworkBindPlugin.kt`
*   **职责**：核心网络绑定逻辑，处理 WiFi 绑定、Captive Portal 绕过、系统设置修改及状态监听。
*   **类与状态**：
    *   `heldCallback`：保存 `requestNetwork` 回调，用于解绑清理 (`NetworkBindPlugin.kt:59`)。
    *   `lastBoundNetwork`：记录上次绑定网络，避免重复清池 (`NetworkBindPlugin.kt:63`)。
    *   `cm`：`ConnectivityManager` 单例 (`NetworkBindPlugin.kt:65-66`)。
    *   `guardPrefs`：SharedPreferences `network_settings_guard`，用于系统设置快照 (`NetworkBindPlugin.kt:309-311`)。
    *   `KEY_AVOID_BAD_WIFI` / `KEY_CAPTIVE_PORTAL_MODE`：Global 设置键名 (`NetworkBindPlugin.kt:314-315`)。
*   **关键命令方法**：
    *   `bindToWifi(invoke: Invoke)`：候选筛选，优先 `NET_CAPABILITY_INTERNET`；直绑 `bindProcessToNetwork`；回退路径使用 `requestNetwork` 显式 `removeCapability(NET_CAPABILITY_INTERNET)` 以兼容 Captive Portal；返回值 `{bound, path, reason}` (`NetworkBindPlugin.kt:69-165`)。
    *   `unbind(invoke: Invoke)`：调用 `bindProcessToNetwork(null)` 恢复默认路由，注销回调 (`NetworkBindPlugin.kt:168-175`)。
    *   `acceptWifiNetwork(invoke: Invoke)`：探测 Hidden API `setAcceptUnvalidated` 可达性；尝试路径：1. `already_validated`；2. Hidden API 反射调用；3. `Settings.Global` 写入；返回 `{accepted, path, reason, hiddenApi}` (`NetworkBindPlugin.kt:192-238`)。
    *   `ensureAvoidBadWifi(invoke: Invoke)`：确保 `network_avoid_bad_wifi=1`。需 `WRITE_SECURE_SETTINGS` 权限，否则返回 `no_permission`。记录快照后写入 (`NetworkBindPlugin.kt:366-402`)。
    *   `restoreAvoidBadWifi(invoke: Invoke)`：按快照还原 `avoidBadWifi` 值 (`NetworkBindPlugin.kt:409-421`)。
    *   `restoreWrittenSettings(invoke: Invoke)`：还原所有写入的 Global 设置 (`NetworkBindPlugin.kt:429-446`)。
    *   `getSecureSettingsStatus(invoke: Invoke)`：查询权限状态及设置当前值 (`NetworkBindPlugin.kt:454-468`)。
    *   `startWifiWatcher(invoke: Invoke)`：注册 WiFi 变化监听，上报 `available`, `lost`, `validated`, `unvalidated` 事件 (`NetworkBindPlugin.kt:506-541`)。
    *   `stopWifiWatcher(invoke: Invoke)`：注销监听 (`NetworkBindPlugin.kt:544-554`)。
    *   `getWifiSsid(invoke: Invoke)`：只读获取 SSID。API 33+ 检查 `NEARBY_WIFI_DEVICES` 权限，低版本恒未授权 (`NetworkBindPlugin.kt:569-577`)。
    *   `reportWifiUnusable(invoke: Invoke)`：调用 `reportNetworkConnectivity(wifi, false)` 触发系统重验证 (`NetworkBindPlugin.kt:586-618`)。
    *   `requestWifiSsidPermission(invoke: Invoke)`：请求运行时权限，幂等处理 (`NetworkBindPlugin.kt:627-636`)。
    *   `wifiSsidPermissionCallback(invoke: Invoke)`：权限回调处理 (`NetworkBindPlugin.kt:639-642`)。
*   **辅助方法**：
    *   `describe(caps: NetworkCapabilities)`：生成能力摘要字符串 (`NetworkBindPlugin.kt:472-476`)。
    *   `hasVpn(manager)`：检测 VPN 活动 (`NetworkBindPlugin.kt:479-485`)。
    *   `snapshotGlobalKey(context, key)`：记录 Global 键原值到 SharedPreferences，已有快照不覆盖 (`NetworkBindPlugin.kt:322-331`)。
    *   `restoreGlobalKey(context, key)`：从快照写回并清除快照 (`NetworkBindPlugin.kt:347-358`)。
    *   `canReachSetAcceptUnvalidated()`：反射探测 Hidden API 是否存在 (`NetworkBindPlugin.kt:241-251`)。
    *   `trySetAcceptUnvalidated(manager, network)`：反射调用 Hidden API (`NetworkBindPlugin.kt:254-268`)。
    *   `applyNetworkSettingsCompat(context)`：写入 Global 设置，含错误处理 (`NetworkBindPlugin.kt:284-298`)。
    *   `readSsid()`：通过 `WifiManager.getConnectionInfo` 读取 SSID，去除引号 (`NetworkBindPlugin.kt:647-656`)。

#### `android/src-tauri/gen/android/app/src/main/java/com/campuslogin/client/generated/RustWebViewClient.kt`

*   **关键实现**：
    *   **成员变量**：`currentUrl` 记录当前 URL，`interceptedState` 记录资源拦截状态，`pendingUrlRedirect` 处理重定向延迟 (`RustWebViewClient.kt:18-21`)。
    *   **资产加载器**：构建 `WebViewAssetLoader`，域名为 `Rust.assetLoaderDomain` (`RustWebViewClient.kt:23-26`)。
    *   **资源拦截**：`shouldInterceptRequest`：若有 `pendingUrlRedirect`，延迟加载并重置标志；若启用 Asset Loader，委托给 `assetLoader`；否则调用 `Rust.handleRequest`，强制设置 `Cache-Control: no-store`，记录拦截状态 (`RustWebViewClient.kt:32-55`)。
    *   **URL 覆盖**：`shouldOverrideUrlLoading`：委托给 `Rust.shouldOverride` (`RustWebViewClient.kt:57-62`)。
    *   **页面开始**：`onPageStarted`：更新 `currentUrl`，若之前未被拦截，重新注入 `initScripts` (`RustWebViewClient.kt:64-73`)。
    *   **页面结束**：`onPageFinished`：调用 `Rust.onPageLoaded` (`RustWebViewClient.kt:75-77`)。
    *   **错误恢复**：`onReceivedError`：针对 `ERROR_CONNECT` 且为主框架、非上次拦截 URL 的情况（通常是 OAuth 重定向导致的连接拒绝），停止默认错误页，强制 `loadUrl` 重试，并设置 `pendingUrlRedirect` 以触发后续正确加载 (`RustWebViewClient.kt:79-97`)。

#### `android/src-tauri/gen/android/app/src/main/java/com/campuslogin/client/generated/RustWebChromeClient.kt`
*   **职责**：处理 Web Chrome 事件：JS 对话框、媒体权限、文件选择、控制台日志。
*   **关键实现**：

### 6. 权限与安全配置
#### `android/src-tauri/gen/schemas/acl-manifests.json`
*   **职责**：定义所有插件的细粒度权限控制列表（ACL）。
*   **核心权限模块定义**：
    *   **biometric**：默认暴露 `allow-authenticate` 和 `allow-status` (`acl-manifests.json:1`)。
    *   **campus-keystore**：默认暴露 `allow-encrypt` 和 `allow-decrypt` (`acl-manifests.json:14`)。
    *   **campus-monitor-service**：默认暴露大量命令，包括生命周期控制、UI 更新、系统设置、安装能力、探针窗口、电池/电源状态 (`acl-manifests.json:30`)。
    *   **campus-network-bind**：默认暴露以下命令以强制流量走 WiFi：`bindToWifi`, `unbind`, `acceptWifiNetwork`, `ensureAvoidBadWifi`, `restoreAvoidBadWifi`, `restoreWrittenSettings`, `getSecureSettingsStatus` (`acl-manifests.json:1`)。
    *   **core:app**, **core:event**, **core:image**, **core:menu**, **core:path**, **core:resources**, **core:tray**, **core:webview**, **core:window**：各自默认权限集 (`acl-manifests.json:105-450`)。
    *   **notification**：默认全开权限 (`acl-manifests.json:650`)。
    *   **opener**：默认暴露 `open-url`, `reveal-item-in-dir`，定义 Scope Schema 支持通配符和变量 (`acl-manifests.json:720-735`)。

#### `android/src-tauri/gen/schemas/capabilities.json`
*   **职责**：将 ACL 中的权限组合成“能力集”（Capabilities），并绑定到具体的 Tauri 窗口。
*   **default 能力集**：
    *   **Identifier**: `default`。
    *   **Target Windows**: `["main"]`。
    *   **Local**: `true`。
    *   **Permissions List**: 组合了四个核心插件的默认权限：`core:default`, `biometric:default`, `opener:default`, `notification:default` (`capabilities.json:1`)。
    *   **隐含缺失**：此能力集**未**显式包含 `campus-keystore`, `campus-monitor-service`, `campus-network-bind` 的权限。

#### `android/src-tauri/gen/android/app/src/main/res/xml/file_paths.xml`
*   **职责**：`FileProvider` 路径白名单，收窄暴露面。
*   **关键路径**：
    *   `<external-files-path name="my_images" path="Pictures/" />`：供相机拍照使用 (`file_paths.xml:11-13`)。
    *   `<files-path name="update" path="update/" />`：供 MonitorServicePlugin 安装 APK 使用 (`file_paths.xml:14-16`)。
    *   **注释指出**：移除了原有的 `external-path` 和 `cache-path` 全量映射，防止越权暴露 (`file_paths.xml:3-9`)。

## Data Flow

1.  **构建流程**：
    *   `build-apk.ps1` 调用 `vite build` -> 产出前端资源。
    *   `build-apk.ps1` 调用 `tauri android build` -> 触发 `Cargo.toml` -> `build.rs` -> 生成 Android 插件代码。
    *   `build.rs` 读取 `COMMANDS` 数组，生成对应的 Java/Kotlin 绑定桩代码。
    *   `RustPlugin` 在 Gradle 构建时创建 `BuildTask`。
    *   `BuildTask.assemble` 调用 Node.js 执行 Tauri CLI，生成 Rust 动态库 (`*.so`)。
    *   构建产物合并到 JNI Lib Folders。

2.  **运行时调用链 (Rust -> Android)**：
    *   **Rust Monitor Loop**:
        *   调用 `CampusMonitorService.begin_probe_window()` -> `run_mobile_plugin("beginProbeWindow")` -> `MonitorServicePlugin.beginProbeWindow` -> `ForegroundService.beginProbeWindow()` (静态调用，持锁)。
        *   调用 `CampusMonitorService.get_power_state()` -> `run_mobile_plugin("getPowerState")` -> `MonitorServicePlugin.getPowerState` -> 返回 `{screenOn, wifiConnected}`。
        *   调用 `CampusMonitorService.end_probe_window()` -> ... -> `ForegroundService.endProbeWindow()` (释放锁)。
    *   **UI/Control Flow**:
        *   JS/Tauri Webview 调用 `startMonitor` -> `MonitorServicePlugin.startMonitor` -> `Context.startForegroundService` -> `ForegroundService.onStartCommand`。
        *   JS 调用 `updateNotification` -> `MonitorServicePlugin.updateNotification` -> `NotificationManager.notify`。
        *   JS 调用 `installApk` -> `MonitorServicePlugin.installApk` -> `FileProvider` URI -> System Package Installer。
    *   **System Events**:
        *   `BootReceiver.onReceive` -> `startForegroundService` (如果用户开启了自启)。
        *   `ForegroundService.registerNetworkWatcher` -> `onCapabilitiesChanged` -> `nudge()` (持短锁唤醒 CPU)。

3.  **IPC 数据流**：
    *   前端 JS 调用 `tauri::plugin::biometric::authenticate` -> Tauri Core 检查当前窗口的 Capabilities -> 查找 `acl-manifests.json` 中 `biometric` 模块的 `allow-authenticate` 命令是否被许可 -> 若许可，则调用后端 Rust 实现；否则抛出权限错误。
    *   JS `postMessage` -> `Ipc.postMessage` -> `Rust.ipc` (JNI)。
    *   WebView 加载 URL -> `RustWebView.loadUrl` -> 检查 `Rust.shouldOverride` -> 决定是否拦截。
    *   `RustWebViewClient.shouldInterceptRequest` 处理资源加载，可能调用 `Rust.handleRequest` 或 `assetLoader`。

## Known Issues

1.  **权限缺失风险**：`capabilities.json` 仅绑定了 4 个默认权限。如果前端代码尝试调用 `campus-keystore` 或 `campus-monitor-service` 的命令，而 `capabilities.json` 中没有添加对应的权限字符串（如 `"campus-keystore:default"`），Tauri 将直接拦截并报错，导致功能不可用。这是最显著的潜在配置陷阱。
2.  **Opener Scope 安全性**：`opener` 的 `global_scope_schema` 允许使用变量（如 `$DATA`）。如果前端传入的路径包含恶意构造的变量解析结果，可能导致意外文件暴露。虽然 Tauri 有沙箱，但路径解析需谨慎。
3.  **WebView 创建限制**：`core:webview` 的默认权限未包含 `create_webview`。这意味着在当前配置下，JS 层无法动态创建新的 WebView 窗口，只能操作已存在的窗口。
4.  **自适应图标依赖**：`ic_launcher.xml` 依赖于 `ic_launcher_foreground`。如果构建过程中缺少该资源，Android 编译可能失败或图标显示异常。
5.  **硬编码路径**：`BuildTask.kt` 中硬编码了 Node.js 和 Tauri CLI 的绝对路径 (`C:\...`, `E:\...`)，这在跨机器构建时会失败，需改为相对路径或使用环境变量 (`BuildTask.kt:19, 52`)。
6.  **Gradle 插件持久化**：`settings.gradle` 中手动声明插件路径，是因为 Tauri CLI 自动生成的 `tauri.settings.gradle` 存在 Bug，会遗漏手写插件，导致 `ClassNotFoundException` (`settings.gradle:6-11`)。
7.  **开机自启限制**：`BootReceiver` 仅拉起服务和 Activity，不保证立即进入监控循环；需用户首次交互或系统允许后台弹出界面才能完整恢复 (`MonitorServicePlugin.kt:416-417`)。
