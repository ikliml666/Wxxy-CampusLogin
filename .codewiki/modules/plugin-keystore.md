## Overview

`plugin-keystore` 是 Tauri 2.0 移动端的密钥库插件，旨在为 Android 平台提供基于 `AndroidKeyStore` 的 AES-GCM 加解密能力。该模块主要解决密码等敏感数据在应用内部存储时的安全性问题，作为桌面端 DPAPI 的移动端替代方案。它通过 Rust 宿主层封装 Kotlin 原生实现，向前端暴露统一的加密和解密命令权限，确保密钥不出安全硬件（TEE），且前端代码无需处理复杂的密钥管理逻辑。

## Key Components

### Rust Host Layer (Tauri Plugin)

位于 `android/plugins/keystore/src/lib.rs`，负责与 Tauri 核心交互及调用移动端原生插件。

*   **Structures & Models**
    *   `CampusKeystore<R: Runtime>` (`src/lib.rs`, 第 24-40 行): 插件的核心包装结构体。
        *   字段: `PluginHandle<R>` (私有，通过 `self.0` 访问)。
    *   `EncryptResult` (`src/lib.rs`, 第 15-17 行): JSON 反序列化结构体，用于接收加密结果。
        *   字段: `data: String` (Base64 编码的 IV + Ciphertext)。
    *   `DecryptResult` (`src/lib.rs`, 第 20-22 行): JSON 反序列化结构体，用于接收解密结果。
        *   字段: `text: String` (解密后的明文)。
    *   `CampusKeystoreExt<R: Runtime>` trait (`src/lib.rs`, 第 42-50 行): 扩展 Trait，允许任何实现了 `Manager<R>` 的类型获取 `CampusKeystore` 实例。
        *   方法: `fn campus_keystore(&self) -> &CampusKeystore<R>` (`src/lib.rs`, 第 43 行定义，第 46-50 行实现)。

*   **Public Functions**
    *   `init<R: Runtime>() -> TauriPlugin<R>` (`src/lib.rs`, 第 52-60 行): 插件初始化入口。
        *   使用 `Builder::new("campus-keystore")` 构建插件。
        *   `setup` 回调中：通过 `api.register_android_plugin(PLUGIN_IDENTIFIER, "KeystorePlugin")` 注册 Android 插件 (`src/lib.rs`, 第 56 行)。
        *   将 `CampusKeystore` 实例存入 Tauri 状态管理 (`app.manage`) (`src/lib.rs`, 第 57 行)。
    *   `pub fn encrypt(&self, text: &str) -> Result<String>` (`src/lib.rs`, 第 30-33 行): 执行加密操作。
        *   调用 `self.0.run_mobile_plugin("encrypt", ...)` 向 Android 发送请求。
    *   `pub fn decrypt(&self, data: &str) -> Result<String>` (`src/lib.rs`, 第 36-39 行): 执行解密操作。
        *   调用 `self.0.run_mobile_plugin("decrypt", ...)` 向 Android 发送请求。

*   **Constants**
    *   `PLUGIN_IDENTIFIER` (`src/lib.rs`, 第 12 行): `"com.campuslogin.plugin.keystore"`，仅在 `#[cfg(target_os = "android")]` 下定义。

### Android Native Layer (Kotlin)

位于 `android/plugins/keystore/android/src/main/java/com/campuslogin/plugin/keystore/KeystorePlugin.kt`，实现具体的 AndroidKeyStore 交互。

*   **Classes**
    *   `@TauriPlugin class KeystorePlugin(activity: Activity)` (`KeystorePlugin.kt`, 第 31-89 行): Tauri 插件的主类。
        *   Companion Object Constants:
            *   `KEY_ALIAS`: `"campus_login_master"` (`KeystorePlugin.kt`, 第 34 行)。
            *   `IV_LEN`: `12` (`KeystorePlugin.kt`, 第 35 行)，GCM 初始向量长度。
            *   `TAG`: `"CampusKeystore"` (`KeystorePlugin.kt`, 第 36 行)，日志标签。
        *   Methods:
            *   `private fun getOrCreateKey(): SecretKey` (`KeystorePlugin.kt`, 第 39-54 行): 从 AndroidKeyStore 获取或生成 AES-256 密钥。使用 GCM 模式，无填充。

    *   `@InvokeArg class EncryptArgs` (`KeystorePlugin.kt`, 第 21-23 行): 加密参数容器。
        *   字段: `lateinit var text: String` (`KeystorePlugin.kt`, 第 22 行)。
    *   `@InvokeArg class DecryptArgs` (`KeystorePlugin.kt`, 第 26-28 行): 解密参数容器。
        *   字段: `lateinit var data: String` (`KeystorePlugin.kt`, 第 27 行)。

## Data Flow

1.  **Initialization**:
    *   Tauri App 启动时，调用 `init()` (`src/lib.rs`, 第 52 行)。
    *   `Builder` 创建插件实例，并在 `setup` 阶段通过 `register_android_plugin` 链接到 Android 层的 `KeystorePlugin` (`src/lib.rs`, 第 56 行)。
    *   `CampusKeystore` 实例被注册到 Tauri 的状态容器中 (`src/lib.rs`, 第 57 行)。

2.  **Encryption Flow**:
    *   前端调用 `invoke("encrypt", { text })`。
    *   Rust 宿主层 `CampusKeystore.encrypt` (`src/lib.rs`, 第 30 行) 序列化参数并调用 `run_mobile_plugin`。
    *   Android 层 `KeystorePlugin.encrypt` (`KeystorePlugin.kt`, 第 56 行) 接收调用。
    *   `getOrCreateKey()` (`KeystorePlugin.kt`, 第 39 行) 检查或生成 AES-256 密钥（别名 `campus_login_master`）。
    *   使用 `Cipher.getInstance("AES/GCM/NoPadding")` (`KeystorePlugin.kt`, 第 60 行) 初始化加密。
    *   执行 `cipher.doFinal` (`KeystorePlugin.kt`, 第 63 行)。
    *   将 IV 和 Ciphertext 拼接并进行 Base64 编码 (`KeystorePlugin.kt`, 第 65 行)。
    *   返回 `JSObject` 包含 `data` 字段 (`KeystorePlugin.kt`, 第 66 行)。

3.  **Decryption Flow**:
    *   前端调用 `invoke("decrypt", { data })`。
    *   Rust 宿主层 `CampusKeystore.decrypt` (`src/lib.rs`, 第 36 行) 序列化参数并调用 `run_mobile_plugin`。
    *   Android 层 `KeystorePlugin.decrypt` (`KeystorePlugin.kt`, 第 73 行) 接收调用。
    *   对输入 `data` 进行 Base64 解码 (`KeystorePlugin.kt`, 第 77 行)。
    *   验证长度大于 IV 长度 (`IV_LEN=12`) (`KeystorePlugin.kt`, 第 78 行)。
    *   提取前 12 字节作为 IV，其余作为密文 (`KeystorePlugin.kt`, 第 80 行)。
    *   使用相同的密钥和 GCM 参数初始化解密 (`KeystorePlugin.kt`, 第 80 行)。
    *   执行 `cipher.doFinal` (`KeystorePlugin.kt`, 第 81 行)。
    *   将明文转为 UTF-8 字符串并返回 (`KeystorePlugin.kt`, 第 83 行)。

## Known Issues

*   **密钥别名硬编码**: `KEY_ALIAS` 固定为 `"campus_login_master"` (`KeystorePlugin.kt`, 第 34 行)。如果多个应用或插件使用相同别名，可能导致冲突。
*   **IV 长度假设**: 代码硬编码 IV 长度为 12 (`KeystorePlugin.kt`, 第 35 行)，虽然 GCM 通常推荐 12 字节，但未做动态适配。
*   **错误处理细节**: 异常被捕获并记录日志，但仅返回通用错误消息 (`KeystorePlugin.kt`, 第 68-69, 86-87 行)，前端难以区分具体失败原因（如密钥不存在、格式错误等）。
*   **仅限 Android**: 当前实现完全针对 Android (`src/lib.rs`, 第 11 行 `#[cfg(target_os = "android")]`)，不支持 iOS。
