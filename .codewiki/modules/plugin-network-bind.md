## Overview
`plugin-network-bind` 是 CampusLogin 项目的 Tauri 移动端插件，核心功能是将 Android 进程的网络流量强制绑定到 WLAN（Wi-Fi）。该插件解决了校园网认证前（Captive Portal）场景下的网络连通性问题，并提供了对系统网络设置（如 `network_avoid_bad_wifi`）的读写与还原能力。

插件通过 Kotlin 实现 Android 原生逻辑，通过 Rust 提供 Tauri API 接口。主要解决两个陷阱：
1. **校园网过滤问题**：认证前的校园 WiFi 被系统判定为无互联网能力，需特殊筛选逻辑。
2. **requestNetwork 拒绝问题**：显式移除 `NET_CAPABILITY_INTERNET` 以避免 AOSP WifiNetworkFactory 拒绝请求。

## Data Flow

1.  **Binding Process (`bindToWifi`)**:
    *   Rust calls `bind_to_wifi()` (Line 19).
    *   Kotlin retrieves all networks (Line 84).
    *   Filters candidates: First tries networks with `NET_CAPABILITY_INTERNET`, falls back to any WiFi (Line 92-94).
    *   Attempts `bindProcessToNetwork` (Line 98).
    *   If fails (e.g., VPN active or rejected), enters fallback path using `requestNetwork` with explicit `removeCapability(INTERNET)` (Line 125-128).
    *   Callback `onAvailable` triggers final binding (Line 131-143).
    *   Result returned to Rust via `invoke.resolve()` (Line 79).

2.  **Setting Acceptance (`acceptWifiNetwork`)**:
    *   Rust calls `accept_wifi_network()` (Line 26).
    *   Checks if network is already validated (Line 217).
    *   Attempts Hidden API reflection `setAcceptUnvalidated` (Line 225).
    *   If hidden API fails, attempts writing `Settings.Global` keys (`captive_portal_mode=0`, `network_avoid_bad_wifi=0`) (Line 233).
    *   Returns status and reason (Line 236-237).

3.  **Avoid Bad Wifi Management**:
    *   `ensureAvoidBadWifi`: Checks permission `WRITE_SECURE_SETTINGS` (Line 334). Reads current value (Line 376). If != 1, snapshots old value to `SharedPreferences` (Line 390) and writes 1 (Line 391).
    *   `restoreAvoidBadWifi`: Reads snapshot from `SharedPreferences` (Line 416) and writes it back to `Settings.Global` (Line 352).

4.  **WiFi Watcher**:
    *   `startWifiWatcher` registers a `NetworkCallback` (Line 535).
    *   Listens for `available`, `lost`, and `capabilitiesChanged` events (Line 515-532).
    *   Emits `wifiChanged` event to Rust via `trigger` (Line 497) only when `VALIDATED` state flips (Line 529).

## Known Issues

1.  **VPN Interference**: `bindProcessToNetwork` returns `false` if an active VPN is present. Reason string includes `_vpn_active` (Line 40, 120). User must disable VPN to proceed.
2.  **Captive Portal Filtering**: Historically, filtering by `NET_CAPABILITY_INTERNET` excluded campus WiFi before authentication. Fixed by prioritizing but not requiring INTERNET capability (Line 29-33).
3.  **requestNetwork Rejection**: Including `NET_CAPABILITY_INTERNET` in `NetworkRequest` causes rejection by AOSP `WifiNetworkFactory` for captive portals. Explicitly removed (Line 37, 127).
4.  **Hidden API Limitations**: `setAcceptUnvalidated` is blocked by hidden API restrictions on most devices. Falls back to `Settings.Global` write, which requires `WRITE_SECURE_SETTINGS` (often only available via adb/shizuku) (Line 186, 273-275).
5.  **SSID Access**: On Android < 33, getting SSID requires `ACCESS_FINE_LOCATION` and location services enabled. Plugin does not request this permission, so SSID is always empty on older versions (Line 562-563). On Android 12+, `NetworkCallback` info has SSID masked; must use `WifiManager.getConnectionInfo` (Line 565-566).
6.  **SecurityException for requestNetwork**: Missing `CHANGE_NETWORK_STATE` permission causes `requestNetwork` to fail immediately. Added to manifest (Line 9).
