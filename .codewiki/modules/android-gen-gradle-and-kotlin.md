## Overview
本模块负责 Android 原生工程壳的构建配置、依赖管理与 Rust 后端集成。它由 Tauri CLI 自动生成（标记为 `autogenerated`），但包含大量针对特定项目需求的手动修补与持久化声明。核心功能包括：
1. **Gradle 构建系统配置**：定义编译 SDK、签名配置、产物命名规则及 ProGuard 混淆规则。
2. **Rust 插件集成**：通过自定义 Gradle Plugin (`RustPlugin`) 和 Task (`BuildTask`)，在 Android 构建流程中自动调用 Node.js/Tauri CLI 编译 Rust 动态库并链接 JNI。
3. **多 ABI 支持**：支持 `arm64-v8a`, `armeabi-v7a`, `x86`, `x86_64` 四种架构，并提供 Universal 变体合并逻辑。
4. **手写插件持久化**：由于 Tauri CLI 生成的 `settings.gradle` 存在缺陷，手动插件路径被硬编码在 `settings.gradle` 顶部以确保构建稳定性。

## Data Flow
1.  **Initialization**: Gradle 启动，解析 `settings.gradle`。首先加载手动声明的插件路径，然后加载 `tauri.settings.gradle` 中的自动声明路径。
2.  **Project Evaluation**: `app/build.gradle.kts` 应用 `rust` 插件。`RustPlugin.apply` 配置 NDK flavor dimensions 并注册任务。
3.  **Task Dependency Graph Construction**: `afterEvaluate` 块建立任务依赖。例如，`mergeUniversalDebugJniLibFolders` 依赖于 `rustBuildUniversalDebug`，后者又依赖于具体的 `rustBuildArm64Debug` 等。
4.  **Execution**:
    *   Gradle 调度 `BuildTask`。
    *   `BuildTask.runTauriCli` 使用硬编码的 Node.js 路径和 Tauri CLI 脚本路径。
    *   Tauri CLI 执行 Rust 编译，生成 `.so` 文件。
    *   Gradle 将这些 `.so` 文件复制到对应的 `jniLibs` 目录。
5.  **Packaging**: Android Plugin 打包 APK，包含 Java/Kotlin 代码、资源以及刚生成的 Native 库。ProGuard 对 Java 层进行混淆。

## Connections
*   [[tauri-core]]: Tauri CLI 生成的核心文件，定义了 Rust 侧的配置和部分自动生成的 Android 代码。
*   [[tauri-plugins]]: 手写插件（如 `network-bind`, `keystore`）的源码位于 `android/plugins/` 目录下，通过 `settings.gradle` 中的相对路径引用。
*   [[node-js-cli]]: `BuildTask` 中硬编码调用的 `@tauri-apps/cli` 入口脚本，负责协调 Rust 编译和 Android 脚本生成。
