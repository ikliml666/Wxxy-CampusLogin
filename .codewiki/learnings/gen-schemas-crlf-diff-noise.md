## 现象

一次构建后 `git status` 出现 `gen/` schemas 与插件 permissions 的全文件 diff，内容看着没变。

## 根因

构建过程把行尾由 `\n` 重写为 `\r\n`，属生成阶段的行尾噪音。当前工作区即处于该状态：`git ls-files --eol` 对这些生成物报 `i/lf w/crlf`（仓库内是 LF、构建后被写成 CRLF）。

## 解决

提交前 `git checkout --` 还原这些文件。

## 教训

`gen/` 下的自动生成物在构建后必然有行尾噪音，**提交前先还原**，不要把这些 diff 混进业务提交（见 [[android-generated-project-discipline]]）。

**区分内容变更与行尾噪音**：插件 ACL / 命令面变更时，`acl-manifests.json` 与 `*-schema.json` 的**内容**变化（新增权限项）是应该提交的——本轮 `fac6407` / `796f8a3` / `6cbee74` 三个提交即携带这类内容变更入档；只有"内容语义零变化、仅行尾被重写"的那种才是噪音。

**判据与陷阱**：本机 `core.autocrlf=true`（Git for Windows 系统配置），比对时 CRLF 被规范化掉，`git status` 可能显示干净——这不等于"构建没动过这些文件"。要确认得看 `git ls-files --eol`（`w/crlf` 即被重写）；换机器或改 `core.eol` / 给生成物加 `-text` 属性后，同一现象就会以整文件 diff 的形式冒出来。
