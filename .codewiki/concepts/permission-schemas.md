## Overview

`permission-schemas` 是 Tauri Android 插件体系中用于定义、验证和自动生成权限校验逻辑的核心概念。它基于 JSON Schema 标准，为每个 Rust/Kotlin 插件命令（Command）声明其所需的系统权限或应用权限。这些 Schema 文件在构建时由 `tauri-plugin` 基础设施读取，并生成对应的 TOML 权限配置文件及运行时检查代码，从而确保原生层操作的安全性与合规性。

该概念贯穿了安全存储、前台服务保活以及网络绑定等核心模块，实现了“声明即校验”的自动化权限治理模式。

## Involved Modules

1. **rust-plugins-keystore**: 负责敏感数据加解密，依赖 `AndroidKeyStore` 硬件级安全能力。
2. **rust-plugins-foreground-service**: 负责前台服务、WakeLock/WifiLock 管理及电池优化引导，涉及系统级通知与电源管理权限。
3. **rust-plugins-network-bind**: 负责 Wi-Fi 绑定、Captive Portal 处理及安全设置读写，涉及位置信息与系统设置权限。

## Flow

`permission-schemas` 的数据与控制流遵循“定义 -> 编译生成 -> 运行时校验”的路径：

1. **定义阶段 (Schema)**:
   在每个插件的 `permissions/schemas/` 目录下维护 `schema.json`。该文件描述了插件暴露给前端的 Command 列表及其元数据（如权限需求）。
   *   **Keystore**: 定义 `encrypt` 和 `decrypt` 命令。
   *   **Foreground Service**: 定义 `startMonitor`, `stopMonitor`, `updateNotification`, `setBootAutostart`, `isBootAutostartEnabled`, `installApk` 等命令。
   *   **Network Bind**: 定义 `bindToWifi`, `acceptWifiNetwork`, `ensureAvoidBadWifi`, `getSecureSettingsStatus`, `restoreAvoidBadWifi`, `restoreWrittenSettings`, `unbind` 等命令。

2. **构建阶段 (Generation)**:
   在 `build.rs` 执行期间，Tauri 构建脚本解析上述 JSON Schema。
   *   根据 Schema 内容，自动生成 `permissions/autogenerated/commands/<command_name>.toml` 文件。
   *   这些 TOML 文件被打包进应用的 Capabilities 配置中，或在运行时作为权限白名单使用。

3. **运行时阶段 (Enforcement)**:
   *   **Rust 侧**: 当前端通过 `invoke` 调用特定命令时，Rust 插件层会检查当前上下文是否具备 Schema 中声明的权限。若不具备，则拒绝执行或返回错误。
   *   **Kotlin 侧**: 部分插件（如 Network Bind）在 Kotlin 实现中可能直接引用生成的权限常量，或在启动时向系统申请 Schema 中定义的 Android Manifest 权限（如 `ACCESS_WIFI_STATE`, `WRITE_SECURE_SETTINGS`）。

4. **前端反馈 (UI Feedback)**:
   前端模块（如 `frontend-network-module` 中的 `DnsAdapterCard`）在调用底层 IPC 前，可通过查询权限状态来决定 UI 展示（例如显示 ADB 命令复制按钮而非直接操作），形成闭环。
