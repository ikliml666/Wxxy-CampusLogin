# 桌面设置页不对称修复：延迟计算选项折叠 + 两列重排（左单卡右三卡） + 删固定网关行

日期：2026-09-28 ｜ 范围：tauri-app/frontend/src/settings/SettingsPanel.tsx（桌面端 Windows）

## 背景

用户报告桌面设置页在 1317/1462px 两档下两列底缘参差形态不同，且随分辨率变化（附截图）。右列（通知与安全+质量检测）远高于左列（启动设置+数据管理），「固定网关地址」只读行占据右列底部却没有交互价值（2026-09-20 起后端固定匹配 10.2.127.254，不再提供手填入口）。要求：①修复不同分辨率下的不对称 ②删除固定网关地址 ③调整卡片使其对齐。

## 改动

1. **「延迟计算选项」折叠**（低频表单折叠策略，Hindsight kp-743c7236）：质量检测卡内 enable-quality 行下新增折叠按钮（aria-expanded + ChevronDown rotate-180），默认收起，包住跳过TTFB/跳过内容开关组与 TTFB 解释框。头文本复用既有 i18n 键 `settings.latencyCalcOptions`，zh/en 零改动。质量卡高度 181px（折叠态）。
2. **删「固定网关地址」行**及其前后两个 Separator；i18n 键 `settings.fixedGateway*` 留置不删（zh/en.json 另一会话在途，且后端字段保留）。
3. **两列重排（两步迭代，用户实测驱动）**：初版「数据管理↔质量检测互换列」（左=启动+质量检测折叠，右=通知与安全+数据管理）把底缘差收到 313px，但用户复看截图仍判「空了一大片」。终版改为**左列=启动设置单卡，右列=通知与安全+数据管理+质量检测（折叠）三卡**——六种整卡配比（三种 2+2、四种 3+1）中唯一把两列差压进三位数内（313/413/591/**81**/626/969/1069）。大卡独占左列、三张轻卡叠右列的形态在视觉上成立，因启动设置卡内部自带三段分组标题。
4. 顺带删除孤儿注释（:80-81 固定网关草稿注释，其 state 早已不存在）。

## 结果与验证

- 列底缘差 413px → 313px（初版）→ **81px（终版，left 1333 / right 1414）**，且 1280/1462/1920 三档**完全恒定**（设置区定宽容器不随窗宽回流）——「不对称随分辨率变化」的表象消除；残差 81px 由页面级新手指引横幅收口。
- `tsc --noEmit` exit 0；CDP 实测 **24/24**（三档 × 打开设置/折叠默认收起/网关 ABSENT/折叠时跳过TTFB隐藏/展开显示解释框/复收隐藏/gridKids=2/两列底缘测量）+ 9 截图。

## 教训

块移动脚本锚点把列闭合 `</div>` 一并吃进卡块 → 左列闭合落入右列内部，JSX 嵌套变成 grid>左列>[启动,Q,右列[N,D]]（tsc 仍通过、页面渲染成单列堆叠），列探针 `children.length>=2` 才暴露。**块级 DOM 搬移后必须断言网格 children 数与两列底缘，不能只看 tsc**；锚点一律从新鲜读取的字面行构建。另：DOM 断言用的文案串要先对 i18n 实文（zh.json 「跳过TTFB检测」无空格、「TTFB（首字节时间）」），否则断言空转（hasTtfbRow 恒 false 的假通过）。
