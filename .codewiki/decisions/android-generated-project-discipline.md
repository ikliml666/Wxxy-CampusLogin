## 背景

Tauri 的安卓工程由 CLI 生成（`gen/android/`），生成物与手改内容混在一起，且包名/签名证书直接决定用户侧数据能否延续。

## 决策

- `gen/android/` **版本化提交**，但 build 产物不入库；
- `settings.gradle` 插件声明为**手改**（会被构建覆盖，需还原）；
- 构建再生的 `\n`→`\r\n` 行尾差异是噪音，提交前 `git checkout --` 还原；
- **改 identifier（包名）= 用户卸载重装**（Keystore 密钥按包名隔离），必须同步 gradle namespace / applicationId / MainActivity 包路径三处并 `git mv` Kotlin 目录；
- **签名证书一经发布不可更换**；
- **插件命令面权限三件套必须同提交**：新增插件命令要同步改 `android/plugins/<插件>/permissions/default.toml`、`permissions/autogenerated/reference.md`、`permissions/schemas/schema.json`，并带上 `android/src-tauri/gen/schemas/` 的三个 schema（`acl-manifests.json` / `android-schema.json` / `mobile-schema.json`）——本仓 tauri build.rs 不为新插件命令生成 per-command toml，生成物就是这三类，漏带即命令被 ACL 拒绝。

## 理由

旧文档记载包名破坏性的依据是"Keystore 密钥按包名隔离"；签名不可更换未记录理由。

## 备选方案

旧文档未记录。

## 影响与约束

任何触碰 identifier 的改动都要按破坏性发布对待；FileProvider authority `${applicationId}.fileprovider` 与 `file_paths.xml` 也必须随之确认。`gen/android/.../AndroidManifest.xml` 属版本化的手改点：新增系统权限必须落在这里（本轮电池白名单补 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`），与 Kotlin 侧调用成对，缺一则运行时静默失败或抛异常。
